## Overview

This is a CMS (CERN) tracking analysis package for measuring **impact parameter (IP) and primary vertex (PV) resolution** in Run 3 data (2022–2024) across JetHT and ZeroBias datasets. It lives inside a CMSSW release (`CMSSW_15_0_16`) and follows the standard CMS package structure.

The workflow has two stages:
1. **EDAnalyzer** (`EDAnalyzers/`) — runs inside CMSSW via `cmsRun` to produce flat ROOT ntuples from MiniAOD
2. **Analysis macros** (`analysis/`) — standalone ROOT/Python scripts that read those ntuples and produce resolution plots and JSON outputs

  RunOnData=True GlobalTag=124X_dataRun3_v15 \

Key parameters:

## Analysis Macros

Fitting and sample-specific scripts live in `analysis/macros/JetHT/` and `analysis/macros/ZeroBias/` (run from the respective directory). All plotting macros are shared in `analysis/macros/plotting/` and take the sample as first argument (run from `plotting/`).

### IP resolution (`ip_res.cc`)
JetHT (since 2026-11-13): fits each unbiased IP histogram with a symmetric double-sided Crystal Ball (`RooCrystalBall`, n ≤ 100) and with a sum of 3 Gaussians (json suffix `_3g`), each also convolved with the mean PV error (`_conv`), plus quadrature subtraction (`_pvsub`), stat. errors (`_err`) and the model-free counted half-width (`_counted`). Categories: vs pT in 9 |η| slices (`pt_eta0..8`, edges in binning.json) + `pt_alleta`; vs η / φ for 1–3 and 3–10 GeV; probe tracks 1 < pT < 15 GeV, |η| < 2.5. Writes results to JSON files in `/eos/home-k/kakang/IPres/analysis/<sample>/json/<period>/ip_res/`.

```bash
# Single job locally
root -b -q 'ip_res.cc("<period>", <job_number>)'   # e.g. ip_res.cc("2023", 0)

# Condor batch (one job per pt/eta/phi bin: 50 for JetHT)
python ip_res.py <period>    # e.g. python ip_res.py 2023
```

### PV resolution (`pv_res.cc`)
Measures PV resolution via random track-splitting (two sub-vertices). Same structure as `ip_res.cc`.

```bash
root -b -q 'pv_res.cc("<period>", <job_number>)'
python pv_res.py <period>
```

### Plotting (`analysis/macros/plotting/`)
Reads the fit JSON outputs and draws data/MC resolution curves (per period) and multi-era overlays. An optional last argument redirects figures to `<outdir>/figures/...` instead of the sample storage dir (useful for before/after comparisons).

```bash
root -b -q 'draw_ip_res.cc("<sample>", "<period>")'   # e.g. draw_ip_res.cc("JetHT", "2023")
root -b -q 'draw_pv_res.cc("<sample>", "<period>")'
root -b -q 'compare_ip_res.cc("<sample>")'            # overlays all eras on one canvas
root -b -q 'compare_pv_res.cc("<sample>")'
root -b -q 'compare_polar_ip_res.cc("<sample>")'      # IP resolution vs phi, polar plots
python list_ip_results.py <sample>                     # bar charts across eras at target pT values
python list_pv_result.py <sample>
```

Tuple paths per era/dataset are configured in `tuplelist.json` in each macro directory. Figures are saved to `/eos/home-k/kakang/IPres/analysis/<sample>/figures/`.

## Architecture

### EDAnalyzer — `Residuals.cc`

The single EDAnalyzer plugin performs three operations per event:

1. **Trigger filtering** — requires `HLT_ZeroBias_v*` (ZeroBias) or any `HLT_PFHT*_v` (JetHT)
2. **IP resolution** — for each track in the refitted PV, refits the PV *without* that track (unbiased vertex), then records `d0` and `dz` relative to the unbiased vertex (`pv_trk_d0_pvunbiased`, `pv_trk_dz_pvunbiased`)
3. **PV resolution** — randomly splits PV tracks 50/50 (random seed derived from run/lumi/event, so the split is reproducible and independent of job grouping), refits two sub-vertices, records both positions, errors and covariances (`pv_x_p1/p2`, `pv_covXY_p1`, etc.) for difference-based resolution and pulls

The PV refitting uses `VertexReProducer` (DA clustering + AVF fitter, **no beam-spot constraint**), which wraps the standard CMS offline primary vertex algorithm, including its track filter (e.g. transverse IP significance w.r.t. the beam line < 4, which truncates the d0 tails). Input tracks come from `packedPFCandidates` with `pvAssociationQuality >= 2`; high purity is *not* required (stored as `pv_trk_isHighPurity`). The transient tracks of the refitted PV are reused for all unbiased/split refits. All distances are stored in **microns** (`micron = 10000`), covariances in micron².

Since `Track-v20261019` the tree also stores, per track, the unbiased-PV covariance (`pv_trk_pvunbiased_{x,y,z}Error`, `covXY/XZ/YZ`), hit-pattern summaries and charge, and per event the beam spot (`bs_*`) and `ev_lumi`. These are meant for subtracting the vertex uncertainty from the IP resolution: per track, err_PV,dxy² = J C Jᵀ with J = (sinφ, −cosφ, 0) and err_PV,dz² with J = (cosφ·sinhη, sinφ·sinhη, −1) (verified against `Track::dxy/dz`). Unused branches of earlier versions were dropped.

`ResTree` (`interface/Tree.h`, `src/Tree.cc`) is the flat TTree wrapper. The sentinel value for missing data is `-777` (`null`).

### Analysis macros shared functions (`analysis/functions/`)

- `tdrStyle.cc` / `CMS_lumi.cc` — CMS plot style and luminosity labels
- `draw_funcs.cc` — canvas setup helpers
- `plot_common.cc` — shared plotting config: sample → storage dir / label, period list, lumi labels, colors/markers, `load_fits()` (reads `fit_<i>.json`), the 24-entry IP plot table `ip_plots()`, and the multi-era overlay `draw_period_overlay()`
- The resolution fit (`fit_res`) is **not** shared: each `ip_res.cc` / `pv_res.cc` defines its own copy. JetHT (since 2026-10-21): the track loop lives only in `macros/JetHT/fill_hists.cc` (see Last Session); ZeroBias still has the old per-bin loops
- `compare_gr.cc` — two-panel data/MC overlay with ratio pad, used by `draw_ip_res.cc` and `draw_pv_res.cc`
