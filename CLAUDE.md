## Overview

This is a CMS (CERN) tracking analysis package for measuring **impact parameter (IP) and primary vertex (PV) resolution** in Run 3 data (2022–2024) across JetHT and ZeroBias datasets. It lives inside a CMSSW release (`CMSSW_15_0_16`) and follows the standard CMS package structure.

The workflow has two stages:
1. **EDAnalyzer** (`EDAnalyzers/`) — runs inside CMSSW via `cmsRun` to produce flat ROOT ntuples from MiniAOD
2. **Analysis macros** (`analysis/`) — standalone ROOT/Python scripts that read those ntuples and produce resolution plots and JSON outputs

## Running the EDAnalyzer

### Local test run
```bash
cmsRun TrackingAnalysis/EDAnalyzers/test/residuals.py \
  RunOnData=True GlobalTag=124X_dataRun3_v15 \
  EventScale=100 EventModulo=0 SampleType=JetHT
```

Key parameters:
- `RunOnData` — `True` for data, `False` for MC (controls pileup branch filling)
- `SampleType` — `"ZeroBias"` or `"JetHT"` (selects which HLT trigger to require)
- `EventScale`/`EventModulo` — process only events where `(event_number - 1) % EventScale == EventModulo`; set `EventScale=0` to process all events

## Analysis Macros

Parallel macro directories exist for `JetHT` and `ZeroBias` under `analysis/macros/`. Run from the respective macro directory.

### IP resolution (`ip_res.cc`)
Fits unbiased IP distributions per pT/η/φ bin using double-Gaussian RooFit models. Writes results to JSON files in `/eos/home-k/kakang/IPres/analysis/<sample>/json/<period>/ip_res/`.

```bash
# Single job locally
root -b -q 'ip_res.cc("<period>", <job_number>)'   # e.g. ip_res.cc("2023", 0)

# Condor batch (submits 200 jobs)
python ip_res.py <period>    # e.g. python ip_res.py 2023
```

### PV resolution (`pv_res.cc`)
Measures PV resolution via random track-splitting (two sub-vertices). Same structure as `ip_res.cc`.

```bash
root -b -q 'pv_res.cc("<period>", <job_number>)'
python pv_res.py <period>
```

### Drawing resolution curves (`draw_ip_res.cc`, `draw_pv_res.cc`)
Reads all JSON outputs for a period, draws resolution-vs-pT/η/φ plots.

```bash
root -b -q 'draw_ip_res.cc("<period>")'
root -b -q 'draw_pv_res.cc("<period>")'
```

### Multi-era comparisons
```bash
root -b -q 'compare_ip_res.cc'   # overlays all eras on one canvas
root -b -q 'compare_pv_res.cc'
python list_ip_results.py         # bar charts across eras at target pT values
python list_pv_result.py
```

Tuple paths per era/dataset are configured in `tuplelist.json` in each macro directory. Figures are saved to `/eos/home-k/kakang/IPres/analysis/<sample>/figures/`.

## Architecture

### EDAnalyzer — `Residuals.cc`

The single EDAnalyzer plugin performs three operations per event:

1. **Trigger filtering** — requires `HLT_ZeroBias_v*` (ZeroBias) or any `HLT_PFHT*_v` (JetHT)
2. **IP resolution** — for each track in the refitted PV, refits the PV *without* that track (unbiased vertex), then records `d0` and `dz` relative to the unbiased vertex (`pv_trk_d0_pvunbiased`, `pv_trk_dz_pvunbiased`)
3. **PV resolution** — randomly splits PV tracks 50/50, refits two sub-vertices, records both positions (`pv_x_p1/p2`, etc.) for difference-based resolution

The PV refitting uses `VertexReProducer` (DA clustering + AVF fitter), which wraps the standard CMS offline primary vertex algorithm. Input tracks come from `packedPFCandidates` with `pvAssociationQuality >= 2`. All distances are stored in **microns** (`micron = 10000`).

`ResTree` (`interface/Tree.h`, `src/Tree.cc`) is the flat TTree wrapper. The sentinel value for missing data is `-777` (`null`).

### Analysis macros shared functions (`analysis/functions/`)

- `tdrStyle.cc` / `CMS_lumi.cc` — CMS plot style and luminosity labels
- `draw_funcs.cc` — canvas setup helpers
- `find_res.cc` / `fit_res.cc` — core Gaussian/double-Gaussian fitting logic used by `ip_res.cc` and `pv_res.cc`
- `compare_gr.cc` — two-panel data/MC overlay with ratio pad, used by `compare_ip_res.cc` and `compare_pv_res.cc`
